Understanding errors

Learning pathRunning PythonFoundationsErrorsPlanningSmall projects

An error is a clue about what Python couldn’t understand or do. Read the message, look at the code around the indicated line, and test one change at a time.

How to read a traceback: Python usually shows where it was running code, followed by the error type and message near the bottom. The indicated line is a useful starting point; the cause can also be earlier, such as an unclosed quote or bracket.

SyntaxError

Meaning: Python can’t read the code as a valid Python instruction—like a sentence with broken punctuation.

Look for: a missing colon after an if, loop, or function; unmatched brackets; or misplaced punctuation.

if score > 5
    print("Yes")

The decision line needs a colon. Check that line and the lines immediately before it.

Unterminated string literal

This is a kind of SyntaxError. A string literal is text written directly in quotes. Unterminated means Python reached the end of the line without finding the expected closing quote.

print("Hello)

Look for: a missing or mismatched quote. Use matching single or double quotes; double quotes can surround an apostrophe, as in "Let's go!".

IndentationError

Meaning: The spaces at the beginning of a line don’t fit the block Python expects.

Look for: a missing indent after a colon, an unexpected indent, or inconsistent indentation. Four spaces per level are a common convention; avoid mixing tabs and spaces.

NameError

Meaning: Python can’t find a name where you used it.

Look for: spelling and capitalization, a missing assignment, or text that should have been in quotes. score and Score are different names.

TypeError

Meaning: An operation received a kind of value it can’t use that way.

Look for: combining a number with text, or calling a tool with the wrong kind of value. For instance, "3" + 2 mixes text and a number; decide whether you meant text or a calculation.

ValueError

Meaning: The kind of value may be acceptable, but its particular contents aren’t suitable.

Look for: conversions such as int("hello"). A person’s input can contain something other than the number you expected.

IndexError and KeyError

IndexError: A position is outside a sequence, such as asking a two-item list for index 2. Its positions are 0 and 1.

KeyError: A requested dictionary key isn’t present. Check the available keys and their spelling.

ZeroDivisionError and AttributeError

ZeroDivisionError: Code attempted to divide by zero. Check the value of the divisor before dividing.

AttributeError: A value doesn’t have the attribute or method requested. Check the value’s type and the method’s spelling.

A calm debugging routine

  1. Read the error type and message. Find the indicated line.
  2. Compare what you expected with what the code actually says; look just above the line too.
  3. Inspect the values and their types. A temporary print() can help.
  4. Change one thing, run it again, and read the new result. Ask for help or look up the message if you’re still stuck.

An error message may look different in the playground and in a terminal. The underlying clue is still useful. Try the playground or return to the dictionary.
